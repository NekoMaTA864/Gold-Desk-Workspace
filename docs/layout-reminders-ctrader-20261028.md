# 2026-10-28 版型、提醒與 cTrader 接入規劃

本輪在 Pages 模式恢復對話優先、均衡三欄、下單在左；選單位於明暗切換左側。桌面寬度 1000px 起套用完整配置，可開啟分隔線拖拉，窄視窗維持既有自適應。三欄只有兩條分隔線，各調整相鄰兩欄、保留第三欄寬度，整排限制於工作區內。欄位比例使用 gold-bounded-widths-v4，不沿用已封存的獨立寬度偏好。

交易對話帳戶區及共用頁首可開啟提醒設定；沿用 PersonalRulesPanel、gold-personal-rules-v1、changeRules 驗證與儲存前確認。交易對話與回放讀取同一份規則，修改不需跳頁。回放編輯器與對話視窗可共存，因此表單改用 useId 避免重複 ID。

## cTrader 建議（尚未串接）

- 產品以交易對話作主入口，報價、帳戶及送單草稿要標明 cTrader DEMO 與來源時間；回放帳戶只在歷史回放中作獨立練習。
- 平台登入與「連接 cTrader DEMO」是兩個步驟。後者走 cTrader OAuth 授權及帳戶選擇，Client Secret、access/refresh token 留在後端。參考 https://help.ctrader.com/open-api/account-authentication/ 。
- 延續既有 FastAPI broker 路由與 ConversationWorkspace 共享草稿，不另建第二套送單。流程為建立草稿、程式核對個人提醒與風險、人工確認、後端重驗、顯示真實回報；UNKNOWN 保持未知且不可自動重送。
- 提醒仍採簡單欄位：本筆手數、總手數、缺停損、停損情境損失等。後端須依授權帳戶的部位、商品規格與幣別核對；資料不足顯示無法評估。現行個人規則只涵蓋回放，不能把設定畫面可見當作券商委託已套用。
- 正式帳號接入後由後端保存使用者規則及版本，確認券商草稿時核對規則版本；瀏覽器儲存只作本地偏好。行情／帳戶失效應停止確認。
- GitHub Pages 保持靜態公開展示。完整 cTrader 使用一般 frontend build 與受保護常駐後端；目前 loopback 限制須在完成認證、帳戶隔離及持久日誌後另行處理。

本輪不修改 API、券商授權或送單計算。一般後端模式保留原聊天寬高調整；本輪新增三種版型先用於公開展示，提醒入口兩種模式均可用。
