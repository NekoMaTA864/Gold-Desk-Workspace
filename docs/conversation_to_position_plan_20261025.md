# Gold Desk：對話到持倉的產品路徑

狀態：2026-10-25 本地設計與實作規劃；不代表後端、真 DEMO 或公開網站已完成。

## 產品主線

使用者的核心問題不是「我要下哪一筆單」，而是「這個黃金交易想法有什麼依據、風險，以及確認後我的部位變成什麼」。三個頁面承擔同一條工作流程：

1. **交易對話**整理問題與條件。每段回答應明示所用資料、時間和能力限制；需要交易時才展開委託草稿。
2. **歷史回放**呈現可重看的當時盤面、案例、持倉、待成交與成交紀錄。對話頁的詳情入口落在相應分頁，返回對話時保留草稿及已填欄位。
3. **即時看盤**展示獨立來源的外部參考行情。公開 Pages 模式不能把這張圖當作本機回放的成交依據，也不能把模擬持倉稱作券商持倉。

公開版的整條路徑是**本機合成回放／模擬帳戶**。一般後端模式的 cTrader DEMO 必須獨立標示、由受保護 API 提供帳戶資料；未連線、過期或未知不能顯示成 0 筆。沒有真實資金交易。

## 畫面與轉場

| 階段 | 主要畫面 | 使用者應立即看到 | 下一步 |
| --- | --- | --- | --- |
| 提問 | 對話中央 | 建議問題、可輸入的欄位、目前助手模式 | 查看回答或建立草稿 |
| 看依據 | 對話回答內 | 結論、支持／反向訊號、資料來源與時間、缺漏與限制 | 展開案例或回放圖表 |
| 準備委託 | 右側委託草稿 | 方向、手數、價格、停損／停利，未填項清楚標示 | 檢查草稿 |
| 核對 | 原有風險與案例審查 | 版本、個人提醒、案例適用性、未知與拒絕原因 | 使用者確認或返回修改 |
| 確認結果 | 狀態通知與帳戶入口 | 已成交、待成交、拒絕或 UNKNOWN 的真實狀態 | 看部位、待成交或紀錄 |
| 管理部位 | 對話右側摘要／回放完整表格 | 部位方向、手數、進場價、浮動損益與來源；0 筆要明示 | 定位進場、追蹤或人工確認平倉 |

### 導覽規則

- 左側三個主頁維持固定位置與名稱；各頁沿用共用頁首、深灰金色與資料來源提示。
- 對話頁中央是主舞台，右側只顯示「持倉與帳戶」或「委託草稿」其中一個。切換側欄不清除輸入、對話或草稿。
- 對話標題旁常駐**黃金模擬持倉筆數**，點擊打開右側摘要；摘要的「查看持倉與損益」導向歷史回放的完整表格。
- 回放頁持倉、待成交、下單／成交紀錄是不同分頁。限價委託尚未成交時只在待成交，不得算入持倉；平倉後轉入紀錄。
- 公開即時圖必須持續註明外部參考來源，跨至回放或案例時需明示資料源已切換。一般後端 DEMO 的持倉與回放帳戶也須分開。
- 對話回答中的案例、行情、部位入口應落到相應資料位置；返回後保留先前問題及尚未送出的欄位。

## 狀態與安全邊界

所有資料區至少區分：載入中、已驗證但為空、不可用／未連線、資料過期、拒絕、UNKNOWN。浮動損益只可使用對應帳戶與當前有效報價；回放與券商 DEMO 不混算。案例的排名和歷史損益不寫成成功率或交易建議。模型可解釋或提出待確認草稿，但不自動確認或補送 UNKNOWN 委託。

公開版重新載入會回到體驗入口，本機回放狀態依既有機制處理；不得用純前端的持倉顯示冒充持久帳戶。正式多使用者版本要先完成認證、逐資源授權、帳戶隔離與耐久儲存，再顯示私人部位。

## 分階段交付

| 階段 | 內容 | 驗收重點 |
| --- | --- | --- |
| A：本地桌面體驗 | 對話首屏、右側雙面板、持倉筆數與摘要入口、清楚的模擬來源標籤 | 可從提問走到持倉明細；窄桌面仍可操作；既有確認流程未變 |
| B：回答的證據層 | 每則回答附來源、觀察時間、已收棒／回放時點及可展開的數值；案例空結果說明原因 | 不把外部參考圖與合成回放混為一談；缺資料不補零 |
| C：跨頁連續性 | 案例／K 線／部位的深度入口、返回對話、草稿未送出保留、狀態通知直達明細 | 切頁不失去輸入；待成交與已成交流向正確 |
| D：受保護後端 | 認證、資源隔離、持久部位與紀錄、串流重連、版本／冪等／UNKNOWN 重查 | 假串流與權限測試先通過；真 DEMO 最終確認由帳戶擁有者操作 |

目前 A 的主要桌面入口已在本地預覽；B–D 是後續工作，不能在 Pages 靜態展示中宣稱已完成。行動版需在桌面方向確認後另做完整視覺與操作驗收。
